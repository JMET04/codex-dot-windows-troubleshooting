# 电脑离线：本机运行与云端在线通道分别检查

记录日期：2026-10-10。本次检查仍未恢复 Dot 的在线电脑通道，不能称为彻底修复。

## 本轮直接证据

- 当前桌面正式任务接口能读取已完成的目标回合；本机任务服务仍正常响应。
- 桌面日志的 durable WebSocket 通道反复记录 `Unexpected server response: 403`，连接在 ready 前失败。
- 另有 `Workspace routing is unavailable` 错误。它说明客户端没有取得可用工作区路由，不能单独证明操作系统拒绝访问。
- 官方 `codex doctor --json` 检查中，本机初始化和普通 Responses WebSocket 握手通过；可选桌面资源 CDN 检查超时。普通模型连接成功不等于 Dot 的电脑在线通道成功。
- 独立官方本机服务的 `account/read` 返回工作区路由。通过该接口的 `refreshToken=true` 刷新已有会话成功、凭据存储时间变化；随后桌面在线通道仍记录 HTTP 403。因此会话刷新成功也不能当作电脑恢复在线。

独立服务不是桌面连接的持有方；上述检查不证明桌面采用了同一账号、工作区或最新会话缓存。原始诊断记录包含设备信息，保留在本机，未发布。

## 当前结论与下一步

确认的失败点是在线通道握手遭拒。HTTP 403 可能涉及会话、工作区权限、服务端判定或网络路径；只有状态码不足以区分这些原因。没有依据修改系统防护、强抢聊天写入者、删除登录资料或持续重发测试请求。

先核对应用当前账号、工作区、Dot 的电脑连接状态及单独的连接请求。必要时使用应用正式重新登录流程；认证和网站验证应由账号本人完成。若正常登录后同一通道仍遭拒，向官方支持提供版本、时间及脱敏错误，并保留本机与在线通道的区别。

官方网络说明要求 HTTPS 之外的 WebSocket 握手和长连接也能正常通过代理及网络设备；公开连接测试可以辅助诊断，但不应绕过账号或网络安全检查。[官方网络要求](https://help.openai.com/en/articles/9247338-network-recommendations-for-chatgpt-errors-on-web-and-apps)。

Dot 本机访问需要单独启用，并保持电脑与应用在线；仅连接 Codex 或启用同步不等于授权 Dot。已经授权也不保证在线通道始终可用。[官方电脑连接说明](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot)。

本机文件代办与直接鼠标控制仍分别验收。正在准备的桌面动作请求尚未执行，不列为通过。
