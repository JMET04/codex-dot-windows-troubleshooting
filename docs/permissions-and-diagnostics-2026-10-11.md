# 实际权限、启动诊断与剩余故障

记录日期：2026-10-11。以下区分 Dot 自己的工作任务、桌面执行者和独立 CLI；一种执行环境通过不代表另一种也通过。

## 文件请求与中断回执

Dot 原工作任务在已获准写入的工作目录独占创建请求并完整读回。桌面执行者核对授权范围、目标实时空闲状态和请求字段，独占预约后只通过正式桌面工具发送一次。目标实际回合后来显示 `interrupted`，没有助手回复，因此未通过任务指挥验收。

当时桌面应用重启；仅凭时间相关不能确定中断的具体触发者。桌面执行者在恢复可写权限后保存了实际失败回执及终止预约状态。该请求不重发；Dot 本人读回失败回执仍待连接恢复后完成。此模式没有常驻后台执行器，也不授予 Dot 原生电脑控制。

## 保存的完全访问与实际权限不一致

应用保存的本机选择和该聊天的权限快照均为完全访问，自动目标续跑却实际收到 `read-only`、`approval_policy=never`。正式目录权限请求未返回许可；电脑工具拒绝读取应用窗口，消息和 GitHub 写入工具要求审批而无法审批。不能把这归因于用户没有选择完全访问，具体配置传递原因仍未证实。

用户通过普通聊天消息继续任务后，实际运行权限恢复为完全访问。桌面执行者真实写入失败回执，电脑工具也成功读取应用窗口。本机配置中未设置 `default_permissions`，且没有旧的 `sandbox_mode` 或 `[sandbox_workspace_write]`；官方配置读取也确认默认配置档为空。

按用户明确选择的完全访问范围，备份原配置后只增加顶层默认值：

```toml
default_permissions = ":danger-full-access"
```

独立官方 app-server 的 `config/read` 已返回此值，其他配置未改变。这只证明配置已加载；是否解决自动续跑的权限差异，必须由后续真实回合证明。目前未将其记为已修复。更高优先级的管理要求仍然有效，已有 Dot 工作任务的权限不会因此自动扩大。

该默认值仅适用于用户确实要求完全访问的环境。它不是云端 403 修复方法。回滚时对照备份，只撤销自己新增的默认值，不覆盖之后的其他配置。依据：[官方权限配置档](https://learn.chatgpt.com/docs/permissions)、[官方配置字段](https://learn.chatgpt.com/docs/config-file/config-reference)。

## 保留后续启动错误

原只读工具将 stderr 丢弃，服务提前退出时只报告“App-server ended before returning a result”。旧错误没有保存，无法还原。此次工具改为保留最多 12 条错误行，总摘要最多 2000 字符，同时记录子进程退出码。含 Bearer、Authorization、Cookie、密码、密钥、token 或 JWT 标记的整行替换为过滤提示；结果报告仍必须留在本地，不自动上传。

新增测试启动真实的合成子进程：它输出错误及合成凭据、退出码 17，测试确认提前退出能保留原因、旧行有界、凭据不进入摘要。全部 9 项测试通过。更新后的工具还通过真实安装版 CLI 读取指定本机聊天元数据及最新回合状态，未读取对话内容、恢复或发送任务。独立 app-server 的 `notLoaded` 仍不证明桌面聊天实时空闲。

当前安装版 CLI 的帮助明确支持 `--stdio`；此次新的只读初始化成功。因此没有将参数兼容性当作旧初始化错误的根因。

## 云端连接仍未恢复

最新桌面日志仍报告 durable 通道在 ready 前遇到 HTTP 403；Dot 页面显示“正在重连”，恢复对话提示 `Codex app-server is not available`。同一时段本机元数据读取成功，两条链路必须分开诊断。官方会话刷新此次等待超时，没有拿到结果；没有重复请求。更新检查也超时，不能据此声称应用已是最新版。

需要在其他任务完成后，由用户手动重新登录原账号与工作区，以排除会话问题。403 本身不能证明登录失效、账户资格不足或代理出错，也不能证明服务端存在已确认的产品缺陷。未修改登录凭据、代理、安全软件、内部权限状态文件或应用安装包。

官方确实支持 Dot 创建及继续本机 Codex 任务，但计算机连接权限、在线状态和插件权限彼此分开；离线不代表访问授权被撤销。依据：[Dot 电脑与应用连接](https://learn.chatgpt.com/docs/dots/computers-and-apps)。原生控制、本次任务回复、Dot 读回回执以及自动权限续跑仍是独立未通过的验收项。
