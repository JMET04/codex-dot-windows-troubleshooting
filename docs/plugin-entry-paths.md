# 插件安装后的 MCP 入口路径

2026-10-11 的后续检查发现两项可分别复现的故障：桌面 durable 云端 WebSocket 返回 HTTP 403；两个本地插件的工具启动握手中断。修复后者没有恢复前者。

## 实际发现与修复

两个已安装插件的 `.mcp.json` 将脚本写成 `./plugins/<插件名>/scripts/...`，其中一个还声明了内置 CAD 服务。安装目录和被检查的任务目录没有对应的仓库布局，三项原入口的独立启动分别以退出码 2、1、2 结束，并报告文件不存在。

实际脚本在安装包内部。先核对文件存在，再在内存中构造修复配置，只将 `command` 指向电脑现有且已验证的运行程序，将 `args[0]` 指向实际安装入口。未改其余参数、环境或工作目录。这里使用本机绝对路径，因此不公开实际配置文件，也不将私人路径写入共享模板。

第一次探测通过裸 `python` 解析到了缺少 ezdxf 的运行环境；电脑现有 Python 3.12 已有该库，明确指定该解释器后通过。没有下载或安装依赖，不能把探测进程的缺库结果当成桌面进程必然缺库的证明。

候选通过后，逐字节备份原配置，核对原文件哈希未被其他工作修改，再原子写入两份安装配置并回读。实际安装配置在另一工作目录复测：

| 独立 aicad-agent | 通过 | 通过 | 27 | 0 |

仅发送 MCP 初始化、初始化完成通知和工具列表查询，未调用工具执行绘图、编辑文档或控制软件。三个进程均正常结束，无 stderr。

## 工作目录与持久性

不要仅为修正脚本入口就改变服务工作目录。AI 学徒的运行数据默认依赖当前工作目录，改变它可能把数据写进安装缓存。此次修复保留原行为。

OpenAI 的公开解析源码会将显式的相对 `cwd` 连接到插件根目录；没有自动把任意 `args` 中的仓库路径改成安装路径。这是源码依据，实际修复以本机启动结果为准。[官方解析源码](https://github.com/openai/codex/blob/main/codex-rs/codex-mcp/src/plugin_config.rs)。

本次修改的是本机已安装配置，重新安装或更新插件可能覆盖它。源包与其他项目代码没有修改。已有桌面任务是否重新加载工具仍待实际启动日志或工具调用证明；独立进程通过不能代替这项验收。不需要为本次文件修复退出登录或重启应用。

回滚时先核对修复后文件哈希仍与本次记录一致，再恢复各自的原字节备份；如已被其他任务修改，先比较差异，不能直接覆盖。

官方独立本地 app-server 的只读账户和 requirements 查询可完成，但不能证明当前桌面云端的功能资格、工作区路由或握手被接受。匿名后台请求的两条既有路线本轮均为 403，其中已配置代理出现 Cloudflare challenge，不能沿用早先代理返回 401 的结果。

界面上的恢复对话“重试”操作被窗口输入检测拦截，是否提交未核验，未重复点击。没有发送新的月儿任务，也没有重发旧未知请求。
