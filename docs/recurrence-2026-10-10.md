# 复发排查：服务退出不等于授权丢失

同日首次通道测试通过后，Dot 对另一个已授权项目的对接再次失败。本记录保留首次成功的范围，同时记录新的故障；不能把旧测试当成后续稳定性的保证。

## 本机实际证据

- 原 `unelevated` 配置仍保留，近期本机命令能启动。旧沙盒 setup_error 文件时间没有更新，不能把它当作这次的新报错。
- 13:23 本机 app-server 日志记录 `memory allocation of 524288 bytes failed`，连接关闭，随后错误广播；13:26 应用重新启动。
- Windows 当日多次记录 Resource Exhaustion Detector 的事件 2004，包括 13:16。复查时系统提交内存约 29.1 GiB，提交上限约 32.7 GiB，使用率约 89%。
- Dot 的现有委派任务报告桌面工具 `Transport closed`，随后 `Codex app tool request failed`；本机 proxy 报 `os error 10050`，连接的控制 socket 不可用。
- 排查聊天的桌面原生读取已恢复；独立官方 stdio 进程也能读取目标元数据和最新回合状态。独立进程返回 `notLoaded`，仍不能代替桌面实时空闲判断。

这些证据支持把内存容量不足作为服务退出的主要复发因素。尚未证明是哪一个应用存在泄漏，也没有证明增加虚拟内存能修复云端 403 或 placement 错误。

## 已实施与生效边界

原 C、E 盘分页文件设置保留；在空余较多的 D 盘新增初始 16 GiB、最大 24 GiB 分页文件，设置已读回核对，旧设置已本地备份。配置回件保守标注需要重启，随后实查发现 Windows 已在线分配 D 盘 16 GiB 分页文件，实际提交上限约 45.1 GiB、使用率约 65%。另存实时生效证据，未强制重启。**应看实际分配和提交上限，不能只看配置写入成功。**

该容量针对本案例当时的负载和空余磁盘选择，不是通用建议。先核对提交内存峰值、磁盘余量和系统转储需求。分页文件能增加容量余量，不能消除软件泄漏或保证性能。

通信恢复使用安装版官方 app-server 的默认 stdio 路径，不依赖本机已失败的 proxy，也不更改任务权限。状态探测从读取 8 条包含完整项目工具历史的回合，改为只读最新 1 条且 `itemsView=notLoaded`，原报告保留。

Dot 的现有委派任务实际执行该路径后，在 `thread/resume` 收到 `already has an active writer`（错误码 -32600）；`turn/start` 次数为 0。目标没有在生成，并不意味着独立进程能取得写入权。桌面服务仍持有目标时，应由该桌面服务的正式发送入口处理，不能抢占写入者、改锁文件或循环恢复。只读成功不能当成该目标发送成功。

## Dot 任务实际缺少桌面工具

继续核对该委派任务，发现没有暴露 `node_repl`，现有电脑控制入口明确禁用原生电脑 API；应用清单为空，浏览器清单另有 JSON 解析错误。任务未观察目标窗口，输入和发送均为 0。排查聊天能使用 Windows 桌面工具，不代表 Dot 的另一个任务拥有相同工具。读取 SKILL.md 或用户重复授权不能补出缺失的工具。

官方已提供 Work/Codex 的 Windows Computer Use；Dot 文档也提供连接个人电脑、创建或继续本机任务的能力。但实际权限与插件能力取决于执行环境。此案例不能据此断言该 Dot 账号具备所有桌面入口，也不能断言官方完全未开放该功能。

本轮备用方式是：已授权请求保留在私人目录，由排查任务调用持有目标的正式桌面发送接口一次，目标实际回合完成、返回匹配校验码，再把回复写回文件供 Dot 核对。**这属于桌面任务代办与文件回传，不是 Dot 直接控制电脑，也没有后台自动转发服务。** 肩宠项目事件订阅、真实语音及蓝牙仍未验收。

## 如何验证

1. 读取实际提交上限和分页文件使用情况；尚未生效时在保存工作后重启，再确认分配。此案例已实查在线生效。
2. 从桌面原生接口取得目标当前状态；只允许对用户已授权、空闲的目标发送。
3. 先写独占发送预约，再发一条固定对接消息，记录返回回合。超时后读取回执，禁止盲目重发。
4. 比较 Dot 委派任务的真实结果和目标聊天实际收到的消息、回复。排查任务自己的只读探测不能算 Dot 的发送成功。
5. 若再次出现资源不足事件或服务退出，保留新时间点继续检查；短期往返成功不能证明长期稳定。

只读探测支持 `--latest-turn`：它只取最新回合 ID 和状态，不返回消息或工具历史。报告仍可能含个人路径与聊天名称，应留在本地。

```powershell
python scripts/probe_local_task.py --codex "<安装版 CLI 路径>" --thread "<已授权目标>" --latest-turn --output "<新的私人报告文件>"
```

## 回退

在 Windows 虚拟内存设置中移除本次新增的 D 盘分页文件设置，并按本地备份核对 C、E 盘原值，然后重启。不要直接删除正在使用的 pagefile.sys。恢复完整历史读取也不会修复代理连接或云端路由；需要内容时另行按页读取必要项目资料。

官方依据：[提交上限与分页文件容量](https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/how-to-determine-the-appropriate-page-file-size-for-64-bit-versions-of-windows)、[内存分配与分页文件增长](https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/slow-page-file-growth-memory-allocation-errors)。
