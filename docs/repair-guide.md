# 修复与回滚步骤

## 1. 先确认连接的是哪一层

打开 Dot 的资料页面，查看自己的电脑是否已连接、是否授权；保持电脑在线、应用打开。Dot 的本机访问权限和 Codex 主机连接、Work Sync 分开设置。连接成功不代表所有历史聊天可访问。

先给一个有明确范围的任务，例如：“在指定工作目录创建一份测试文本，读回相同内容并报告结果。”记录实际启动结果和回件。若命令尚未创建就失败，转入第 2 步；若已经启动但写文件被拒绝，检查该任务的可写目录和正式权限流程。

官方依据：[电脑连接](https://learn.chatgpt.com/docs/dots/computers-and-apps)、[任务能力](https://learn.chatgpt.com/docs/dots/tasks-and-memory)。

## 2. 看初始化错误，不只看‘没权限’的口头描述

在当前使用的 Codex 用户目录下检查 `.sandbox/setup_error.json` 和 `.sandbox/sandbox*.log`；默认用户目录通常是 `%USERPROFILE%\.codex`。不要复制整个配置或秘密目录公开发布。

本案例出现以下错误组合：

```text
helper_unknown_error: setup refresh had errors
runtime read/execute validation failed
node_repl.exe: open ACL target for root-only update
os error 32
```

它表示运行库权限校验/刷新时遇到文件共享冲突，进程还没启动；不是证明用户拒绝了 Dot 授权。官方 [PR #51822](https://github.com/openai/codex/pull/51822) 修复了对已使用 EXE/DLL 打开过宽权限导致的同类冲突。本案例日志与该机制相符，不能据此把所有权限报错都归为同一原因。

若是 error 1385、企业策略拒绝、普通文件拒绝访问或其他错误，按 [Windows 官方指南](https://learn.chatgpt.com/docs/windows/windows-sandbox) 的对应分支排查。

## 3. 为本案例故障选择可用执行环境

先使用应用自身的更新检查确认可用更新，注意源码修复合并不等于当前桌面包已包含修复。不要覆盖桌面应用内置二进制文件。

当前官方文档优先建议兼容设备使用 MXC；本案例没有验证 MXC。若仍需要旧实现，elevated 为首选，unelevated 为环境政策允许时的次级备用方案。后者网络隔离较弱，不支持 denied read paths。企业受管设备应遵守已有实施策略。

本案例的有效变更：

1. 在本地备份当前实际使用的 `config.toml`。备份可能包含敏感配置，勿上传。
2. 找到现有 `[windows]` 段，仅将 `sandbox = "elevated"` 改为 `sandbox = "unelevated"`。
3. 如果没有该段，才追加一个；已有段不要重复。不要改 `approval_policy`、工作目录权限、模型或其它连接。
4. 让新的本机执行调用读取变更，再验证启动。旧任务若缓存旧配置，使用应用提供的正式恢复流程；需要重启时，先妥善结束当前工作。不要强杀其它任务。
5. 保留实际输出、退出状态及读回结果。本案例修改后新的执行调用和 Dot 委派任务都能启动。

这不是把 full access 当成修复，不需要删除权限状态、广泛放开 ACL 或关闭防护软件。

## 4. 验证修复效果

按顺序做：

1. **执行器**：让 Dot 的本机任务实际运行一个无副作用操作。
2. **文件往返**：在已授权工作目录写入随机校验字符串，然后读回并比较。
3. **任务读取**：使用真实可用的本机聊天工具，只读取指定聊天元数据。
4. **任务指令与回复**：仅在有明确授权、目标空闲时，发送单条“只回复校验码，不调用工具”的消息。通过目标真实回合独立读取并核对，不能仅凭发送方说成功。

独立启动的 app-server 返回 notLoaded 只反映那个服务进程的状态，**不能证明桌面任务空闲**。发送前要用实际桌面任务状态检查，不能用旧状态文件冒充新检查。

遇到超时，先读取实际回合和结果文件。不要立即重发。本案例中的超时请求最终完成。

## 5. 云端读取仍报错时

若云端读取报 `unsupported placement format version 1`，但本机工具可读取同一指定目标，分别记录结果。没有证据时，不将其归为本机 Windows 权限问题，也不承诺更改沙盒能修复云端路由。

优先使用任务实际具备的官方本机聊天工具。确实缺失时，可参考官方 app-server 的 stdio 接口；字段以**所安装版本**生成的 JSON schema 为准。本仓库只提供元数据只读示例，不附带任意任务远程控制服务。

## 6. 回滚

记录本次只改过的配置项，恢复其原值。本案例原值为：

```toml
[windows]
sandbox = "elevated"
```

若备份后配置还有其它新变化，只恢复这个键；不要用旧整份配置覆盖后续设置。新版环境验证通过后，可按官方指引选择当前适用的实现。保留原始证据和单次发送预约，避免为了重测而重复任务。

无需重新安装与此次故障无关的技能。
