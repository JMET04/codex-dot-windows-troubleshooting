# 运行中的代理预检与本地备用入口

更新于 2026-10-12。原生 Dot 控制仍未通过当前验收。本地备用聊天的成功与原生 Dot 分别记录。

## 官方功能候选已撤销

安装版 CLI 支持 `respect_system_proxy`，原配置未设置，有效值 false。通过官方命令启用后，新 CLI 进程读取到 true；既有桌面进程是否热加载没有验证。

独立只读 `doctor --json` 对照仅在自有子进程内清除代理环境变量。关闭与开启两次均退出 1：关闭时 provider HTTPS 超时、Responses WebSocket 为 403；开启时 provider 报 TLS 握手或验证失败、WebSocket 超时。组合错误不能进一步断言为某一种证书故障，也不是 Dot 控制链验收。候选未证明恢复，已按哈希精确恢复原配置字节，未退出登录或重启桌面。

## 同一代理的复查结果发生变化

对同一公开后端、同一本机代理执行不带凭据的严格 TLS 预检：

| 检查 | HTTP CONNECT | SOCKS5 远端域名解析 |
| --- | --- | --- |
| 首次协议对照 | 超时 | TLS 验证通过 |
| 后续协议复查 | TLS 验证通过 | 目标 TLS 超时 |

不能据此证明某一种协议稳定可用，也不能确定云端 403 的服务端原因。代理中继 TCP 可连通，同样不足以证明后续 TLS 或认证后的 WebSocket 成功。

社区作者在 [openai/codex #49829](https://github.com/openai/codex/issues/49829) 报告了固定域名透传中继的运行中验证，并发布 [实验代码](https://github.com/rdcamelot/codex-durable-relay)。这是其他环境的作者实测，本机没有运行该项目的安装器、服务或计划任务。

## 限时原型与实际边界

新增 `scripts/bounded_socks_relay.py`，显式选择 HTTP CONNECT 或 SOCKS5，目标固定为 `codex-cloud-backend.chatgpt.com:443`，仅监听固定回环地址。最长运行 180 秒，建立连接有超时，并发和转发字节有限制。它不改 hosts、不安装服务、不读取认证、不解密 TLS、不重发消息，只是可审阅的诊断原型。

该原型需要 Python 3.11 或更新版本。单独启动它不会改变桌面连接路线；本案例没有完成 hosts 映射或原生控制验收，不建议把启动日志当作修复成功。

真实集成检查把监听启动、TLS 客户端和清理放进同一个自有进程。一轮 HTTP 透传完成了 Python 默认 TLS 身份与证书验证；SOCKS5 集成建立上游隧道后，TLS 连接中止。随后 Windows PowerShell、PowerShell 7 与 Node 的严格复查未全部通过，Node 最终超时。上游隧道建立不等于目标 TLS 成功。

一次分离执行的检查错过了限时监听窗口，遇到连接拒绝；已标为监听器缺失，不用它证明上游失败。

用户同意一次标准 Windows UAC 提权，用于最长 60 秒的单域名 hosts 试验。管理员脚本在 TLS 预检阶段失败，**没有应用映射**。原 hosts 字节保持不变，不能将前置检查描述为完成了桌面路线试验。没有继续弹出提权或重发旧 UNKNOWN 任务。

所有真实检查保持证书验证，未使用登录令牌、Cookie、独立认证 WebSocket 或应用包补丁。测试监听器均已关闭。27 项自动测试通过，其中 7 项新测试覆盖固定目标、拒绝认证、超时、取消与关闭；合成测试不是 Dot 接管验收。

## 本地备用入口

用户明确同意新增一个本地聊天。该聊天使用自己的工具：原生窗口枚举成功，报告 6 个窗口；本地聊天读取调用完成；PowerShell 输出无害测试标记，退出码 0。检修聊天另读其调用记录核对来源。

备用聊天报告 `danger-full-access`、审批 `never`，并读取现有私人记忆技能与 Computer Use 技能。未新增安装、监视器或后台服务；未测试鼠标键盘输入，窗口枚举不能代替所有软件控制验收。

它可供用户继续提交具体本机任务。它不替换原生 Your dot，也不证明原生连接、派发或控制已经恢复。最终仍需 Dot 自己产生新执行结果，并在目标处核对实际回合与效果。
