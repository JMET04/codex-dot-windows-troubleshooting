# 桌面更新后的程序路径失效

记录日期：2026-10-10。以下为脱敏实测，保留账号、日志和设备信息在本机。

## 已修复的问题

文件传递工具原来引用桌面应用的某个 CLI 缓存版本目录。桌面更新后旧目录已不存在，新 CLI 位于另一个目录，因此工具在启动本地 app-server 前就会失败。

`resolve_codex.py` 现在在每次启动时发现 Windows 桌面安装目录中的 CLI，选择文件修改时间最新的可用候选，并检查候选仍在该目录内。找不到桌面安装时才查找 PATH；显式指定的程序路径不存在时会直接报错。该发现策略是辅助工具的实现选择，不是桌面应用提供的稳定版本选择接口；多版本同时存在时可通过 `--codex` 指定所需 CLI。

私有文件通道工具已使用同一发现函数。公开的 `probe_local_task.py` 仅做元数据读取，没有恢复任务或发送指令，也没有修改权限、登录信息或桌面应用文件。

## 验证结果与边界

- 当前安装版 CLI 可以启动官方 stdio app-server，读取一个已授权本机聊天的元数据和最新回合 ID、状态。
- 共 7 项测试通过。其中新增测试模拟旧缓存程序被移除、新程序安装后的重新发现，以及显式错误路径不能静默切换程序。
- 当前桌面聊天可以通过官方 Computer Use 工具读取和操作 Codex 窗口；设置中的完整访问和任意应用操控开关均已开启。这只证明当前桌面聊天的能力。
- 月儿收到一次诊断请求，并报告向其已有任务提交后返回 `UNKNOWN`，尚未确认接收。该任务的诊断回执和文件控制请求尚未出现，不能记为月儿控制成功，也不能直接重发未知结果的请求。
- 月儿页面同时出现 `Codex app-server is not available`。桌面在线长连接日志继续记录 WebSocket HTTP 403，偶尔连接重置；界面的“已连接”不能作为任务可执行的证据。

独立启动的只读 app-server 返回的 `notLoaded` 仅描述该独立服务，不证明桌面应用中的聊天已经停止。登录状态读取成功也不证明云端长连接或任务授权成功。

## 仍需排查的连接

已安装应用的静态源码显示，在线长连接使用 `codex-cloud-backend.chatgpt.com`。匿名升级探测在现有代理路径超时，在另一次请求级直连探测返回 403。匿名请求没有应用的认证信息，因此这些结果不能确定已认证桌面连接被拒绝的原因，也不能据此判断功能资格。
