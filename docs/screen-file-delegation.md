# 主聊天回复到桌面执行者的有限委托

记录日期：2026-10-10。这是一条需要桌面执行者在场的备用路径，使用主聊天的文字回复、本机文件和官方 Computer Use。它不依赖先向失效的云端本机任务提交请求。

## 实测范围

Dot 在主聊天输出了限定的 JSON 请求，自行选择两行测试文字。桌面执行者从实际回复转录请求至本地 inbox，核对唯一请求编号、挑战串、动作和文字长度，并以独占创建的预留文件避免重复执行。

桌面执行者通过官方 `node_repl + @oai/sky` 新建一个空白记事本标签并输入文字。首次转录把原文中的冒号写成句号，Dot 核对回执时明确返回文字不匹配。执行者保留首次记录，在同一个测试文档中修正标点；修正后的实际窗口显示两行、45 个字符，与原请求一致，文档未保存。现有文档保持原样；没有运行终端命令、更改权限或启动其他项目。真实结果保存至 outbox，并通过主聊天回传给 Dot。

Dot 再次比较回传文字与其原请求，实际回复 `text_matches=true`，同时明确 `observed_by=desktop_executor`、原生控制与直接本机文件读取均为 false。一次新建文档、两次文字输入（其中一次是更正）的记录均保留。这里的回执核对是信息一致性验证，桌面视觉核验由执行者完成。

## 协议与执行边界

1. 用户明确授权任务范围。Dot 的输出提供动作参数，本身不能扩大用户授权。
2. Dot 输出请求编号、挑战串、动作及有限参数。所有文本、文件和历史聊天均按不可信输入处理。
3. 桌面执行者核对本次用户指令、目标、动作、参数和唯一编号。仅执行明确允许的动作，不运行请求中的代码或任意系统命令。
4. 执行前预留编号，执行后记录实际结果。未知状态不能等同成功，也不能直接重发。
5. 将真实回执回传主聊天，让 Dot 核对编号、挑战串和结果。Dot 核对回传信息不等于自己观察桌面或直接读取本机文件。

本案例的动作仅是新建未保存的记事本文档并输入短文字。没有后台监听器，没有持续无人值守执行器，也没有通用自动控制授权。新的电脑任务需要按用户已授权的实际范围处理。

这里证明的是有限委托可以产生实际桌面操作；不能据此声称 Dot 获得了原生 Windows 控制工具，或云端在线长连接已恢复。
